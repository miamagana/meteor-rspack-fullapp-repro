# Blaze full-app repro for meteor/meteor#14561

`meteor test --full-app` (and `meteor build`) never load the client Rspack
bundle, so the client app never boots. `meteor run` (dev) is fine.

This branch is a Blaze + rspack full-app app. It lives under `tests/` (not
`test/`) on purpose, so it does not also trip #14514.

## Why Blaze

The bug is in `packages/rspack`'s `getImportContent`: for a Blaze client it
short-circuits and never emits the client bundle import, so `client-meteor.js`
loads nothing. `blaze-html-templates` is what makes `isMeteorBlazeProject()`
true and triggers that path.

## Observing it

The reliable signal is the plain-JS side effect `window.__CLIENT_BOOTED__ = true`
in `client/main.js`. If the client bundle never loads, it stays `undefined`.

1. Start the full-app test server (leave it running, no `--once`):

   ```
   meteor test --full-app --port 4100 --driver-package meteortesting:mocha --raw-logs
   ```

2. Drive it with headless Chromium:

   ```
   node drive.js http://localhost:4100/
   ```

### Before the fix (stock 3.4.1 / devel)

- `_build/test/client-meteor.js` has no client bundle import (Blaze
  short-circuit comment instead).
- No `/__rspack__/...` script is injected into the page.
- `window.__CLIENT_BOOTED__` is `undefined`.

### After the fix

- `_build/test/client-meteor.js` no longer imports the bundle.
- The page injects `<script src="/__rspack__/test/client-rspack.js">` after the
  Meteor client runtime, and the server serves it (HTTP 200).
- `window.__CLIENT_BOOTED__ === true`.

## Note on the Blaze template

The `#greeting` Blaze template does not render even after the fix, and the page
logs `jQuery not found` / `Template is not defined`. Those errors show up both
before and after (they come from the Meteor-loaded Blaze packages, not the
client bundle), so Blaze template rendering under rspack is a separate issue
(#14523), independent of #14561. Use `window.__CLIENT_BOOTED__` as the #14561
signal.
